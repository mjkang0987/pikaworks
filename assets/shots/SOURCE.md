## 개인정보

**실제 고객 데이터가 아니다.** 전부 `mjkang0987/tas` 의 시드
(`server/prisma/seed.mjs`)가 만든 가상 데이터다 — 담당자 제인·찰스·
마이클·브로콜리. 매장명과 계정명은 "피카 살롱", 계정 주소는

운영 DB 는 건드리지 않았다.

## 촬영 조건 (2026-08-25, tas@99390ef)

운영 사이트는 이 환경의 프록시가 막아서 접속할 수 없다. 대신 컨테이너에서
직접 띄웠다.

1. `apt-get install postgresql` (16) → `initdb` → `createdb tas`
2. `tas/client` 에서 `pnpm install` → `prisma db push` → `prisma:seed`
3. 로그인: OAuth 키가 없으므로 `AUTH_SECRET` 으로 세션 쿠키를 직접 발급.
   `server/page-data/index.ts` 의 `getPageSession` 이 토큰 **안에서**
   `storeId`·`role` 을 읽으므로 `sub` 만으로는 안 되고 전체 클레임이 필요하다
4. 시드 예약이 2~4월이라 8월 달력이 비어서, 85일치를 현재 주 전후 30일로
   압축 이동했다. 그 과정에서 생긴 담당자 시간 충돌 2건은 다른 담당자로 옮겼다
5. 촬영 전 정리 — 온보딩 투어는 `localStorage['tas-tour-main-v1']` 를 첫 렌더
   전에 심어서 끄고, AD 플레이스홀더(dev 전용)는 내용이 "AD" 인 span 의 부모를
   지운다(styled-components 해시 클래스라 선택자로는 못 잡는다).
   Next 개발 배지는 셰도루트 안이라 DOM 제거가 안 먹히므로
   `next.config.mjs` 에 `devIndicators: false` 를 넣어 끈다

## 촬영할 때 반드시 확인할 것

**PostgreSQL 이 죽으면 앱이 에러를 내지 않고 조용히 미로그인 화면을 준다.**
실제로 그 상태로 로그인 페이지가 카드에 박힌 채 렌더까지 갔다. 스크린샷만
봐서는 정상처럼 보이므로 눈으로 거르지 못한다.

그래서 촬영 스크립트는 찍기 전에 매번 두 가지를 본다.

- 본문에 "SNS 계정으로 로그인" 이 있으면 즉시 실패
- 각 페이지의 고유 문구(캘린더 `2026`, 고객 `고객 명단`, 매출 `매출`)가
  없으면 즉시 실패
- 데스크톱 샷에 `예약관리` 가 없으면 실패 — 사이드바가 조용히 접힌 채로
  찍히는 것을 막는다
- 화면 어디에든 `example.com` 이 보이면 실패 — 시드 기본값이 다른 화면에서
  새어 나오는 것을 막는다

조용히 잘못된 것을 찍느니 시끄럽게 죽는 편이 낫다.

## 매출 화면을 쓰려면

시드 예약은 `price = 0`, `paymentCompleted = false` 라서 매출 화면이
총 매출 0원, 그래프는 바닥에 깔린 직선으로 나온다. 그대로는 광고에 못 쓴다.
쓰려면 가격과 결제완료를 채워 넣고 다시 찍어야 한다.
지금 카드 구성(5장)에서는 매출 화면을 쓰지 않는다.

다시 찍을 일이 생기면 위 순서를 그대로 반복하면 된다. 서비스 UI 가 바뀌면
스크린샷도 같이 갱신해야 한다 — 옛 화면을 광고에 쓰면 안 된다.

## 촬영 조건 (2026-08-26, clipnote@f121a32)

TAS 와 달리 DB 를 세울 필요가 없다. `middleware.ts` 가 인증 환경변수가
없으면 세션 갱신만 건너뛰므로, Supabase 없이 `pnpm install && pnpm dev`
만으로 `/` · `/clips` · `/login` 이 전부 뜬다.

문제는 **미리보기에 넣을 링크**다. 이 환경의 프록시가 `clipnote.co.kr`·
`pikaworks.kr`·`takeaseat.co.kr` 을 전부 막아서(000/403) 실제 사이트의
메타데이터를 읽을 수 없다. 앱은 이때 "웹페이지가 아니라서 내용을 읽을 수
없어요" 라고 하는데, 프록시가 HTML 이 아닌 것을 돌려줘서 나온 오진이다.

그래서 이렇게 했다.

1. `/etc/hosts` 에 `127.0.0.1 pikaworks.kr` 을 걸고
2. 이 저장소 `app/layout.tsx` 의 **실제** 메타데이터(제목·설명)와 실제
   `public/og.png` 를 그대로 담은 페이지를 로컬 80 포트로 서빙한 뒤
3. ClipNote 에 `http://pikaworks.kr` 을 넣어 앱이 직접 읽게 했다

**화면에 들어간 내용은 전부 실제 값이다.** 카드 배경도 진짜 OG 이미지고
렌더러도 ClipNote 본체다. 로컬로 돌린 것은 DNS 뿐이다.

443 포트는 에이전트 프록시가 이미 쓰고 있어 HTTPS 로는 못 띄운다. 그래서
주소가 `http://` 다. 카드에는 호스트명만 나오므로 카드 영역만 잘라 쓴다.

`next.config.ts` 에 `devIndicators: false` 를 넣어 개발 배지를 껐다.

## 촬영할 때 반드시 확인할 것

찍기 전에 세 가지를 본다. 하나라도 걸리면 즉시 실패한다.

- 본문에 "접근하지 못했어요" 가 있으면 실패 — 메타데이터를 못 읽은 것이다
- 실제 제목(`PIKAWORKS — 일상을 정리하는 작은 도구들`)이 없으면 실패
- 화면에 `localhost` 가 남아 있으면 실패

메타데이터를 못 읽어도 앱은 그라디언트 카드를 정상으로 그려 준다. 눈으로는
멀쩡해 보이므로 검사로만 걸러진다. 그 카드를 광고에 쓰면 실제와 다른 것을
보여주게 된다 — clipnote.co.kr 은 `ogImagePath` 로 대표 이미지를 실제로
내보내기 때문이다.
