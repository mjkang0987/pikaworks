# sns-designer

pikaworks 인스타그램 이미지를 만든다. 직접 그리지 않는다 —
`design` 스펙(JSON)을 쓰고 `scripts/ig.mjs` 가 결정론적으로 렌더한다.
그래서 톤이 저절로 유지되고, 사람은 결과 PNG 만 보면 된다.

## 0. 입력 조건

**`status` 가 `approved` 인 아이디어만 작업한다.**
`proposed` 면 아직 사람 검수를 안 거친 것이므로 손대지 않고 그렇게 말한다.

## 1. 디자인 시스템 — 고정값

**서비스마다 테마가 다르다.** 값은 `scripts/ig.mjs` 의 `THEME` 이 SSOT 이고,
아래 표는 그걸 옮겨 적은 것이다. 어긋나면 코드가 맞다.

| | ClipNote | Take a Seat |
|---|---|---|
| 규격 | 1080×1080 CSS → **2160×2160** 출력 | 〃 |
| 배경 | `#ffffff` (흰색) | `#1c1c1e` (블랙, TAS `--aside-bg`) |
| 글자 | `#18181b` | `#f5f5f7` |
| 액센트 (면·배지) | `#7c5cfc` | `#6526d9` (TAS `--brand-color`) |
| 액센트 (글자) | `#7c5cfc` | `#ba9dee` — `#6526d9` 는 블랙 위 글자로 안 읽힌다 |
| 연한 면 | `#efebff` | `rgba(255,255,255,.07)` |
| 선 | `#e4e4e7` | `rgba(255,255,255,.12)` |
| 마지막 줄 강조 | 보라 **글자** (`coverAccent: 'text'`) | 보라 **형광펜 바** + 흰 글자 (`'marker'`) |
| 커버 배지 | 연보라 면 (`soft`) | 보라 면 + 흰 글자 (`solid`) |
| App Store 배지 | 마감 장에 붙음 | **없음** — 웹 전용 |
| 서체 | Pretendard Variable (`assets/fonts/`, 파일로 박혀 있어 어디서 돌려도 동일) | 〃 |

> `products.js` 의 takeaseat accent `#ec4899` 는 인스타에 쓰지 않는다.
> 새 색이 필요하면 `THEME` 에 정식으로 추가한다 (6절).

**장 구성 — 세 종류다.**

| 장 | 구성 |
|---|---|
| 커버 | 위: 서비스 로고·이름 + 우상단 배지(`kicker`) / 가운데: 헤드라인 + 칩(`features`) / 아래: PIKAWORKS 로고 + "밀어서 보기 →" |
| 내용 | 위: 제목(+부제) / 가운데: 템플릿 본문 / 아래: PIKAWORKS 로고 + 서비스 로고·이름 |
| 마감 | 자동 생성 — 서비스 로고·이름·`tagline` · "프로필 링크를 확인해주세요" · `https://도메인` (+ ClipNote 는 App Store 배지) |

**강조는 커버·내용 모두 같은 규칙이다** — 제목의 **마지막 줄**에 걸린다
(내용 장은 제목이 2줄일 때만). 강조 방식은 위 표의 "마지막 줄 강조" 를 따른다.
다섯 장이 같은 규칙으로 강조해야 한 묶음으로 읽힌다.

## 2. 템플릿 고르기

| 템플릿 | 언제 | 필요한 필드 |
|---|---|---|
| `list` | 항목 3~4개를 나열 (사용자 유형, 기능 묶음, 체크리스트) | `items[{icon,title,text}]` |
| `shot` | **실제 서비스 화면**을 그대로 보여줄 때 | `pc`+`mobile`(+`pcLabel`·`mobileLabel`·`mirror`), 또는 `mobile`(+`wide`) |
| `chat` | 링크 공유처럼 대화창에서 벌어지는 일 | `before`·`after` |
| `source` | 원본 게시물 → 클립 카드로 바뀌는 장면 (ClipNote) | `post{name,overlay[],caption}`·`card{title,desc,domain,tags[]}` |
| `clips` | 저장된 클립 목록, 최대 3줄 (ClipNote) | `items[{title,domain,tags[],overlay[]}]` |
| `panel` | 제품 화면을 흉내 낸 목업이 필요할 때 | `html` |
| `statement` | 한 문장으로 승부 (오해 정정, 선언) | `statement` |

`shot` 의 `mirror: true` 는 PC·모바일 화면 위치를 좌우로 뒤집고 제목도 오른쪽
정렬로 바꾼다 (takeaseat-3 의 2번째 장). `source` 는 남의 계정 게시물을 가져다
쓸 수 없어서 게시물의 구조만 빌린 더미로 그린다 — 로고·브랜드색은 넣지 않는다.

**가능하면 `shot` 을 쓴다.** 도식은 우리가 그린 그림이고 스크린샷은 증거다.
찍을 화면이 없으면 `assets/shots/SOURCE.md` 의 촬영 절차를 따른다.

**항목은 3개 아니면 4개.** 2개는 허전하고 5개는 글자가 줄어 안 읽힌다.

`statement` 는 **한 줄에 들어갈 만큼 짧게** 쓴다. 가운데 정렬 자동 줄바꿈이라
길면 `돼 / 요.` 처럼 단어 중간에서 꺾인다. 길어질 것 같으면 `list` 로 바꾼다.

공용 아이콘: `chat` `bookmark` `folder` `globe` `link` `calendar` `clock`
`users` `coin` `chart` `bell` `check` `sparkle` `lock` `phone` `ticket` `tag`

**돈에는 `revenue` 도 `coin` 도 쓰지 않는다.** `revenue`(TAS 자체 세트)는 달러 `$`,
공용 `coin` 은 엔화 `¥` 글리프다. 원화 서비스 광고에 외화 기호가 박힌다.
금액에는 `point` 를 쓴다 — TAS 가 적립금에 실제로 쓰는 글리프다.

**서비스 저장소에서 가져온 실제 아이콘이 있으면 그걸 먼저 쓴다.**
Take a Seat 은 `assets/icons/takeaseat.json` 에 사이드바가 실제로 쓰는 26개가
들어 있다 (`point` `membership` `coupon` `history` `customers` `booking`
`revenue` `settings` 등). 이름을 틀리면 렌더가 실패하면서 쓸 수 있는 목록을
전부 출력하므로, 외우지 말고 한 번 틀려서 확인하면 된다.

`panel` 안에서 쓸 수 있는 유틸 클래스:
`.grid5` `.grid4` (격자) · `.cell` (흰 칸) · `.cell-on` (보라 강조) · `.cell-off` (점선 비활성)

## 2-1. 장수는 규격이 아니다

**정해진 장수가 없다.** 커버 1장 + 본문 N장 + 마감 1장이고, 마감은 `ig.mjs` 가
`THEME` 에서 자동으로 만든다 (`design.outro` 를 쓰지 않는다). 상한은 10장이다
(`MAX_SLIDES`, `publish.py` 도 같은 값으로 막는다). 즉 **3~10장** 사이는
아무것도 안 고치고 나간다.

`plan.md` 에 `takeaseat-1` 이 5장이었다는 기록이 있는데 그건 그 건의 결과지
형식이 아니다. 실제로 그 줄을 형식으로 읽고 뒤 건들을 5장에 맞춰 만든 적이
있다(2026-08-28). 맞추지 마라.

**장수는 내용이 정한다.**

- 넘길 이유가 장마다 있으면 늘린다. 채우려고 늘리면 중간에 이탈한다
- 짧게 만들려고 줄이지 않는다. 할 말이 남았는데 5장에 욱여넣으면 각 장이 얕아진다
- 캐러셀 슬라이드 수 통설은 7~10장이다. 5장 이하는 짧은 게시물로 읽히고
  10장을 넘으면 스와이프 피로가 온다. 다만 이건 시장 통설이고
  **우리 계정 데이터가 아니다** — 발행이 쌓이면 여기를 우리 수치로 바꾼다

## 3. 커버 카피 가이드

커버가 피드 썸네일이다. **후킹 한 덩어리만 읽히면 성공**이고, 나머지는 밀어서
들어온 사람이 보는 것이다. 그래서 후킹에 크기를 다 몰아줬다 (178px).

### 글자수 — 전부 공백 제외 기준

공백은 한글 글자 폭의 절반도 안 돼서 세지 않는다. `카드 한 장으로` 는 8자가
아니라 **6자**로 친다.

| 필드 | 상한 | 줄 수 | 비고 |
|---|---|---|---|
| `title` 각 줄 | **6자** | **최대 3줄** | 마지막 줄이 강조 줄이 된다 |
| `kicker` | 12자 | 1줄 | 우상단 배지. 없어도 된다 |
| `features` 각 칩 | 10자 | **3개** | 가로 한 줄로 눕는다 |

측정값이다. Pretendard 800 · 178px 기준으로 실제 렌더해서 잰 결과,
빽빽한 한글(`가가가가가가`)은 **줄당 6자에서 폭이 찬다.** 2줄이든 3줄이든 같다.
**4줄은 세로가 안 나와서 아예 못 쓴다.**

### 줄 나누기

- **3줄을 기본으로 삼는다.** 2줄이면 위아래 여백이 넓어져 헐거워 보인다
- 문구를 줄이려 하지 말고 **끊는 위치를 바꾼다.** 같은 문장을 다르게 끊는 건
  카피 변경이 아니라 조판이다
- 의미 단위로 끊는다. `저장할 땐 / 무심하게 / 꺼낼 땐 예쁘게`
- **마지막 줄에 핵심어를 둔다.** 거기에 강조가 걸린다

```
✓  단골 관리, / 아직 / 수첩인가요        3줄, 마지막 줄이 후킹
✓  예약부터 / 매출까지 / 한 곳에         3줄
△  밋밋한 링크를 / 카드 한 장으로        2줄 — 여백이 넓다
✗  줄당 7자 이상                        렌더가 실패한다
```

### 강조

마지막 줄에 자동으로 걸린다. 방식은 서비스마다 다르고 `THEME` 에 박혀 있다.

- **Take a Seat** (블랙 배경) — 키컬러 형광펜 바 + 흰 글자.
  색 하나로 강조와 가독성을 동시에 못 잡아서 강조를 면으로 옮겼다.
  `#6526d9` 를 글자로 쓰면 다크 위에서 2.29:1 이라 안 읽힌다
- **ClipNote** (흰 배경) — `#7c5cfc` 글자 그대로. 흰 배경에선 문제가 없다

### 여백은 건드리지 않는다

패딩·행간·칩 간격은 `ig.mjs` 에 고정이다. 카피만 넣으면 맞게 나온다.
여백이 이상해 보이면 그건 **줄 수 문제**지 여백 문제가 아니다 — 줄을 다시 끊어라.

## 3-1. 내용·마감 슬라이드 카피 길이

| 필드 | 상한 | 비고 |
|---|---|---|
| `slide.title` 각 줄 | 14자 | 2줄까지 |
| `slide.subtitle` | 32자 | 없어도 된다 |
| `items[].title` | 12자 | |
| `items[].text` | 30자 | 항목 간 길이를 비슷하게 |
| `statement` | 60자 권장 | **코드가 검사하지 않는다.** 줄바꿈 자동이라 길면 단어 중간에서 꺾이니 렌더 후 눈으로 확인 |
| `chips` | 8자 · 4개 | 언어 표기 등 |
| `chat` `before/after.tag` | 10자 | |
| `chat`·`source` 카드 `title` / `desc` | 22자 / 34자 | |
| `source` `post.name` / `post.overlay` 각 줄 / `post.caption` | 12자 / 9자 / 24자 | |
| `clips` `items[].title` / 태그 | 22자 / 6자 | |

마감 슬라이드는 카피를 쓰지 않는다. 앱당 한 장으로 고정돼 있고 `THEME` 의
`tagline`·`domain` 에서 자동으로 나온다. 예전 건(takeaseat-3 등)의 `design.outro`
필드는 렌더에 쓰이지 않는 잔재다. `LIMITS` 의 `outro.*` 도 같은 이유로 남아 있다.

## 3-2. 넘치면 어떻게 되나

**렌더가 실패한다.** 조용히 잘리지 않는다.

두 단계로 막는다.

1. **글자수 검사** — 위 표를 넘기면 렌더 전에 멈춘다
2. **실제 폭·높이 측정** — 브라우저에서 잰다. 글자수를 지켜도 실제로 넘치면
   거기서 잡힌다. 요소 자신뿐 아니라 부모 행·칸까지 본다 (배지처럼 내용에
   맞춰 커지는 요소는 자기 자신은 절대 안 넘치고 부모에서 넘친다)

```
Error: 커버 title[0]: "가나다라마바사" 가 공백 제외 7자입니다. cover.title 는 6자까지.
```

## 4. 작업 순서

1. 아이디어 파일을 읽고 `caption` 에서 **이미지로 옮길 한 가지**를 고른다.
   캡션 전체를 이미지에 넣으려 하지 않는다 — 이미지는 후킹, 캡션이 설명이다
2. 템플릿을 고르고 `design` 객체를 아이디어 파일에 써 넣는다
3. 렌더한다

   ```bash
   node scripts/ig.mjs pipeline/ideas/<id>.json
   ```

   `public/ig/<id>.png` 가 만들어지고 `image_path`·`image_url` 이 채워지며
   `status` 가 `design_done` 으로 올라간다.
4. **만들어진 PNG 를 직접 읽어서 눈으로 확인한다.** 아래 체크리스트를 돌린다
5. 문제가 있으면 `design` 을 고쳐 다시 렌더한다. 될 때까지 반복한다
6. 사람에게 PNG 를 보여주고 검수를 요청한다

시안만 보고 싶을 때는 상태 파일을 건드리지 않는 방식이 있다:

```bash
node scripts/ig.mjs <spec>.json --out /tmp/preview.png
```

브라우저를 못 찾는 환경이면 `CHROMIUM_PATH=<chrome 실행파일>` 을 앞에 붙인다.

## 5. 렌더 후 체크리스트

PNG 를 실제로 보고 확인한다. 하나라도 걸리면 고쳐서 다시 렌더한다.

- [ ] 글자가 옆이나 아래로 잘리지 않았나
- [ ] 헤드라인이 의도한 자리에서 줄바꿈됐나 (어색한 위치에서 꺾이면 `title` 을 두 줄로 직접 나눈다)
- [ ] 본문이 위아래로 눌리거나 푸터에 닿지 않았나
- [ ] 보라색이 제목 마지막 줄 강조·배지·아이콘·강조 칸에만 쓰였나 (남발하면 강조가 사라진다)
- [ ] 테마가 서비스와 맞나 — ClipNote 는 흰 배경, Take a Seat 은 블랙 배경
- [ ] 푸터 로고·서비스명과 마감 장 도메인이 서비스와 맞나 (TAS 에 App Store 배지가 없어야 한다)
- [ ] 축소해서 봤을 때 (인스타 피드는 작다) 헤드라인이 읽히나

## 6. 절대 하지 않는 것

**`status` 에 `image_ok` 를 쓰지 않는다.** 그 값은 사람만 쓴다.
`ig.mjs` 도 `design_done` 까지만 올리도록 되어 있다. 손으로 그 위를 넘기지 않는다.

`scheduled` 도 쓰지 않는다 — 발행일 배정은 `/sns-queue` 가 한다.

새 템플릿이나 새 색이 필요하면 그때그때 인라인 스타일로 우회하지 말고
`scripts/ig.mjs` 에 정식으로 추가한다. 우회하면 다음 사람이 톤을 못 맞춘다.
